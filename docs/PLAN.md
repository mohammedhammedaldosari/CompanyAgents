# خطة بناء منصة «شركة الوكلاء»

> المرجع الملزم للسلوك والشكل: `docs/reference/project-doc.md` (وثيقة المشروع).
> ملفات Claude Design (النموذج الأولي) استُخدمت مرجعًا للتصميم والسلوك فقط، ولم تُنسخ بنيتها الداخلية.

## 1. نتيجة مراجعة المرجع

| البند | ما وجدناه في النموذج الأولي | القرار في المنصة الحقيقية |
|---|---|---|
| البنية | ملف HTML واحد بحجم 266 كيلوبايت، دالة فورية واحدة، متغيرات عامة مشتركة | مستودع متعدد الحزم: حزمة نطاق مشتركة + خادم + واجهة، بوحدات صريحة |
| المحرك | المحرك نفسه يعمل في المتصفح، والخادم يشغّله داخل `vm` ويحفظه في `localStorage` مزيف | المحرك يعيش في الخادم فقط كخدمات نطاق فوق قاعدة بيانات، والواجهة عميل رفيع عبر العقد |
| التخزين | ملف JSON واحد يُكتب كاملًا بعد كل تغيير | PostgreSQL بجداول علائقية، معاملات، وترحيلات مرقمة |
| الطابور والجدولة | `setInterval` داخل العملية | `pg-boss` فوق PostgreSQL (طابور تنفيذ + مهام دورية) كما تنص الوثيقة §20 |
| الوكيل | استدعاء واحد للنموذج يعيد نصًا، وموصلات MCP تمرَّر للنموذج مباشرة | حلقة أدوات حقيقية؛ كل استدعاء أداة يمر ببوابة الصلاحيات على الخادم ويُسجَّل |
| ثغرة أمنية | تمرير خوادم MCP للنموذج عبر `mcp_servers` يسمح له بتنفيذ أفعال كتابة (إرسال بريد مثلًا) دون المرور بالبوابة | الخادم هو عميل MCP؛ أدوات القراءة تُنفَّذ مباشرة، وأدوات الكتابة تُصنَّف كأفعال وتخضع للسياسة |
| الموافقة | الموافقة تغيّر الحالة فقط | يُحفظ الاستدعاء كاملًا ويُنفَّذ حرفيًا بعد الموافقة، ثم يُستكمل الوكيل ليكتب النتيجة |
| الدخول | رمز ثابت في الرابط والتخزين المحلي | كلمة مرور للمالك (scrypt)، جلسات مخزنة ومجزأة تنتهي بعد 30 يومًا، ملف تعريف ارتباط HttpOnly، وحد لمحاولات الدخول |
| المؤشرات | أرقام محاكاة تنفلت أحيانًا (ظاهر في لقطة الشاشة: 464253%) | المؤشرات من مصادر حقيقية فقط: مركز البائع، الاستيراد، الإدخال اليدوي، وواجهة الاستقبال |

## 2. المعمارية المستهدفة

```
packages/domain   ← الأنواع، البيانات المرجعية، القواعد النقية (التوجيه، الصلاحيات، الجدولة، الإعداد، التنسيق). تُختبر بلا قاعدة بيانات.
apps/server       ← Fastify + TypeScript + PostgreSQL + pg-boss + Anthropic SDK + عميل MCP
apps/web          ← Vite: واجهة التصميم (three.js، اللوحات، لوحة الإدارة) فوق المحوّل الحي فقط
```

المبادئ:
1. **العقد ثابت** (§18): الواجهة لا تعرف إلا دوال المحوّل والأحداث؛ كل قاعدة عمل على الخادم.
2. **معاملة لكل أمر**: كل أمر من المالك أو المحرك يُنفذ في معاملة واحدة، والأحداث تُبث بعد نجاح الحفظ فقط.
3. **البوابة على الخادم**: لا فعل خارجي دون تقييم السياسة؛ الدفع لا يُنفَّذ أبدًا.
4. **لا بيانات مخترعة في الإنتاج**: المحاكاة تتحول إلى بيانات عرض تجريبية اختيارية (`seed:demo`) منفصلة عن المحرك.
5. **قابلية التوسع**: الأحداث تمر عبر `LISTEN/NOTIFY` لتسمح بتشغيل أكثر من نسخة خادم لاحقًا؛ الطابور في القاعدة.

## 4. معايير القبول للمرحلة الحالية

- كل البيانات تأتي من الخادم عبر العقد نفسه (§18).
- لا يُنفَّذ أي فعل ذي أثر خارجي يحتاج موافقة قبل موافقة المالك (اختبار تكامل).
- كل استدعاء أداة مسجّل في `tool_calls` مع الوكيل والمدخلات والنتيجة ومن وافق.
- تغيير سعر +7% يحتاج موافقة و+4% لا يحتاج بالحد الافتراضي؛ الدفع مقفل (اختبار وحدة).
- الإيقاف يمنع أي استدعاء جديد للنموذج أو الأدوات فورًا.
- إعادة التشغيل لا تفقد أي بيانات؛ المهام الجارية تُستأنف.
